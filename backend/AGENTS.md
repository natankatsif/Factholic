# AGENTS.md — backend

Общий контекст — в корневом `AGENTS.md`. Здесь — правила зоны бэкенда.

## Устройство

- `src/stages/NN-*/` — этап. Файлы: `README.md` (задача и требования), `types.ts` (вход/выход), `mock.ts`
  (примеры входа/выхода + mock-реализация), `real.ts` (настоящая реализация с внешними API), `index.ts`
  (только выбор mock/real через `selectImpl`), `tsconfig.json` (изолированная проверка юнита).
- `src/pipeline/context.ts` — `Stage<I, O>` и `StageContext { jobId, signal, log }`.
- `src/pipeline/orchestrator.ts` — единственное место, где этапы вызываются друг за другом.
- `src/config.ts` — **единственное** место, где читается `process.env` (из корневого `.env`): режим сервера,
  mock/real по этапам, ключи провайдеров, проверка, что для real-этапов заданы ключи.
- `src/server.ts` — HTTP + WS. `SERVER_MODE=replay` — проигрывает `MOCK_EVENTS` вместо пайплайна.

## Правила

1. Этап **импортирует из других этапов только `types.ts` и `mock.ts`**, никогда `index.ts` и внутренние файлы.
   Нарушение связывает юниты и ломает независимые проверки.
2. Экспорт этапа — одна функция с сигнатурой `Stage<Input, Output>`; имя и сигнатуру не меняем без согласования
   (её вызывает оркестратор).
3. Можно добавлять в папку этапа любые свои файлы (`prompt.ts`, `client.ts`, `utils.ts`) — это внутреннее дело юнита.
4. Все внешние запросы получают `ctx.signal`. Логи — через `ctx.log`.
5. Ошибка одного тезиса не должна валить job: этапы 04/05 могут бросать исключение, оркестратор превратит его в
   `FactCheck { status: "failed" }`. Этапы 01/02 при фатальной ошибке бросают — job завершится `job.failed`.
6. Таймкоды везде абсолютные (секунды от начала видео).
7. Ключи и настройки — только через `config` из `src/config.ts` (eslint запрещает `process.env` в других файлах).
   Новая переменная → добавь в `config.ts` (и в `requires` своего этапа, если нужна для real) и в `.env.example`.
8. Пишешь настоящую реализацию — в `real.ts`. `mock.ts` не трогай без нужды: на его данных работают соседи и фронт.
9. Новая npm-зависимость — в `backend/package.json` (`npm i <pkg> -w backend`).

## Проверка

```bash
npm run check -- backend-03     # свой этап изолированно
npm run check -- backend        # весь бэкенд
npm run dev                     # пайплайн end-to-end, сервер на :8787
```
