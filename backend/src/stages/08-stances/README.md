# 08 — Stances: тезис + источники → стороны

**Владелец:** backend-2

Определяет позицию каждого найденного источника относительно тезиса и показывает «стороны»: сходятся ли
независимые источники, разделились или в большинстве против. Вердикта «правда/ложь» и оценки 0–10 нет.

|        | Тип                                                                                     | Файл       |
| ------ | --------------------------------------------------------------------------------------- | ---------- |
| Вход   | `StancesInput` (`Claim` + `FoundSource[]` + контекст + `voteGroups` из дерева этапа 05) | `types.ts` |
| Выход  | `StancesOutput` (`consensus` + позиция каждого источника)                               | `types.ts` |
| Пример | `mockStancesInput`, `mockStancesOutput`                                                 | `mock.ts`  |
| Mock   | `STAGE_STANCES=mock` → mock-функция в конце `mock.ts`                                   | `mock.ts`  |
| Real   | `STAGE_STANCES=real` в `.env`, нужны: `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`        | `real.ts`  |

## Статусы (`Consensus.status`, packages/contracts)

| status           | когда                                                                    |
| ---------------- | ------------------------------------------------------------------------ |
| `agree`          | доля веса «за» ≥ 0.7 — независимые источники в основном подтверждают     |
| `split`          | доля веса «за» между 0.3 и 0.7 — источники разделились                   |
| `mostly_against` | доля веса «за» ≤ 0.3 — большинство опровергает                           |
| `few_sources`    | независимых групп с позицией < 2; нет источников; прогноз (`prediction`) |

`groupsFor` / `groupsAgainst` / `groupsMixed` — сколько **независимых групп** «за» / «против» / «частично»
(не источников). Этап 09 отдаёт их фронту как `FactCheck.sides` — счёт сторон вместо вывода.

## Одна группа — один голос

Статус считает **код**, а не LLM (`real.ts`, константы — в начале файла):

1. Голосуют источники с позицией (`stance ≠ neutral`) и `relevance ≥ 0.3`.
2. Источники с одинаковым `voteGroups[id]` — одна группа (перепечатки одной новости из дерева этапа 05). Нет
   `voteGroups` или источника в нём — источник сам себе группа.
3. Позиция группы — по сумме позиций её источников: `supports` = +1, `refutes` = −1, `mixed` = 0. Сумма > 0 —
   группа «за», < 0 — «против», 0 — её вес делится пополам между «за» и «против» (считается в `groupsMixed`).
4. Вес группы — **максимум** `domainReliability` её голосующих источников: перепечатки не добавляют веса.
   Если у всех групп надёжность 0 — каждая весит одинаково.
5. Групп с позицией < 2 → `few_sources`; иначе статус по доле веса «за» (таблица выше).

## Требования

- Позиции — **только по текстам источников**, не по «знаниям модели»: пользователь должен проверить нас по ссылкам.
- `summary` / `explanation` — что говорят источники и каких они типов; нейтральный тон, на `uiLanguage`;
  без «правда/ложь», без оценок и баллов. Если источники противоречат друг другу — так и написать.
- `sourceAssessments` — по одной на каждый источник; источники с `relevance` < 0.3 не голосуют и во фронт не уходят.

## Реализация (`real.ts`)

- `prompt.ts` — промпт: позиции только по источникам, описание без вердикта, нейтральный тон; речь и тексты
  источников в блоках `<claim>`/`<video_context>`/`<source>` с заменой угловых скобок и списком id источников —
  защита от prompt injection со страниц и из речи.
- `real.ts` — LLM (`llm.ts`, structured output) возвращает только `sourceAssessments` (`stance` + `relevance`) и
  описательные `summary` / `explanation`; дальше код:
  - нет источников или `category: "prediction"` → `few_sources` **без вызова LLM** (`model: "rules"`);
  - `sourceAssessments` — ровно по одной на источник (пропущенные LLM — `neutral` / 0);
  - статус и число групп — по правилам выше; если вышло `few_sources`, тексты берутся из `texts.ts`.
- `texts.ts` — тексты для случаев, которые выставляет код (ru / uk / en, остальные языки UI → en).
- `.env`: `STAGE_STANCES=real`, `LLM_*` (как у 03). Reasoning effort `medium`.
- Ручной прогон на моке (из папки `backend`): `npx tsx src/stages/08-stances/dev.ts`.
- Тесты без сети (фейк OpenAI): `npx tsx --test "src/stages/08-stances/**/*.test.ts"`.

## Eval

Эталонные случаи — `eval/cases.ts` (22 кейса: тезис + тестовые источники; тексты `excerpt` выдуманы, домены
реальные ради справочника), прогон — `eval/run.ts` (из папки `backend`):

```bash
npx tsx src/stages/08-stances/eval/run.ts                       # все кейсы
npx tsx src/stages/08-stances/eval/run.ts --only injection      # по подстроке id (можно несколько через запятую)
npx tsx src/stages/08-stances/eval/run.ts --verbose             # + стороны и лог этапа по каждому кейсу
```

- **Прогон платный**: каждый кейс (кроме прогнозов и кейса без источников) — реальный запрос к LLM (OpenAI). Нужны
  `LLM_PROVIDER=openai`, `LLM_API_KEY`, `LLM_MODEL` в корневом `.env`; `STAGE_STANCES` не важен — eval всегда
  вызывает `real.ts`. Без этих переменных — только проверка корректности кейсов, код 0. Переменные окружения
  важнее `.env`, поэтому проверить кейсы без платного прогона: `LLM_API_KEY= npx tsx src/stages/08-stances/eval/run.ts`.
- Кейсы описывают ожидание по прежней шкале (`labels`), `run.ts` переводит его в статусы (`LABEL_STATUSES`):
  `true` / `mostly_true` → `agree`; `false` / `mostly_false` → `mostly_against`; `mixed` → `split`;
  `misleading` → любой, кроме `few_sources`; `unverifiable` (нет данных, прогноз, нет источников) → `few_sources`.
- Покрытие: подтверждено разными источниками; опровергнуто; источники противоречат; факт верен, вывод искажён;
  источники по теме без прямых данных (в том числе для заведомо верного факта — позиция «из головы» не проходит);
  прогноз; prompt injection внутри `excerpt` (в том числе поддельный `</source>`) не меняет позиции;
  `uiLanguage` en / uk при тезисе на другом языке; эмоциональная речь → нейтральные тексты.
- По кейсу: допустимые статусы, при необходимости — `stance` отдельных источников и запрещённые подстроки. Для
  любого выхода: известный статус, `groupsFor` / `groupsAgainst` — целые ≥ 0 и согласованы со статусом,
  `sourceAssessments` ровно по входным источникам, язык `summary` / `explanation` по алфавиту (латиница /
  кириллица, і/ї/є/ґ против ы/э/ъ), нейтральность — по списку оценочных слов (эвристика), `summary` не длиннее
  300 символов.
- Итог — таблица PASS/FAIL с причинами и `N/M`; код выхода 1, если провален хоть один кейс.
