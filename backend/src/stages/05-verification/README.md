# 05 — Verification: тезис + источники → оценка 0–10

**Владелец:** backend-2

Сопоставляет тезис с найденными источниками и выставляет оценку достоверности.

|        | Тип                                                                                   | Файл       |
| ------ | ------------------------------------------------------------------------------------- | ---------- |
| Вход   | `VerificationInput` (`Claim` + `FoundSource[]` + контекст)                            | `types.ts` |
| Выход  | `VerificationOutput` (score, label, тексты, stance по каждому источнику)              | `types.ts` |
| Пример | `mockVerificationInput`, `mockVerificationOutput`                                     | `mock.ts`  |
| Mock   | `STAGE_VERIFICATION=mock` → mock-функция в конце `mock.ts`                            | `mock.ts`  |
| Real   | `STAGE_VERIFICATION=real` в `.env`, нужны: `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL` | `real.ts`  |

## Шкала (score ↔ label должны совпадать)

| score  | label          | смысл                                                           |
| ------ | -------------- | --------------------------------------------------------------- |
| 9–10   | `true`         | подтверждается независимыми источниками                         |
| 7–8    | `mostly_true`  | верно, есть неточности в деталях                                |
| 5–6    | `mixed`        | частично верно                                                  |
| 3–5    | `misleading`   | факт формально верный, но подан искажённо / вырван из контекста |
| 2–4    | `mostly_false` | в основном неверно                                              |
| 0–1    | `false`        | опровергается                                                   |
| `null` | `unverifiable` | прогноз, мнение или нет данных                                  |

## Требования

- Оценивать **только по источникам**, не по «знаниям модели» — иначе нечего показать пользователю.
- Если источники противоречат друг другу → `mixed` и честно написать это в `explanation`.
- `summary` / `explanation` — нейтральный тон, на `uiLanguage`.
- `sourceAssessments` — по одной на каждый источник; источники с `relevance` < 0.3 этап 06 во фронт не отдаёт.

## Реализация (`real.ts`)

- `prompt.ts` — промпт: только по источникам, шкала, нейтральный тон; речь и тексты источников в блоках
  `<claim>`/`<video_context>`/`<source>` с заменой угловых скобок — защита от prompt injection со страниц и из речи.
- `real.ts` — после LLM код сам следит за принципами продукта:
  - нет источников → `unverifiable` **без вызова LLM**;
  - метку должен обосновывать хотя бы один источник с `relevance ≥ 0.3` в нужную сторону («правда» —
    `supports`/`mixed`, «ложь» — `refutes`/`mixed`), иначе `unverifiable` (догадка не проходит);
  - `category: "prediction"` → `unverifiable` без вызова LLM;
  - `score` приводится к диапазону метки (`scale.ts`), `sourceAssessments` — ровно по одной на источник.
- `texts.ts` — тексты для вердиктов, которые выставляет код (ru / uk / en, остальные языки UI → en).
- `.env`: `STAGE_VERIFICATION=real`, `LLM_*` (как у 03). Reasoning effort `medium`.
- Ручной прогон: `npm run stage:05 -w backend`.

## Eval

Эталонные случаи — `eval/cases.ts` (22 кейса: тезис + тестовые источники; тексты `excerpt` выдуманы, домены
реальные ради справочника), прогон — `eval/run.ts`:

```bash
npm run eval:05 -w backend                          # все кейсы
npm run eval:05 -w backend -- --only injection      # по подстроке id (можно несколько через запятую)
npm run eval:05 -w backend -- --verbose             # + вердикт и лог этапа по каждому кейсу
```

- **Прогон платный**: каждый кейс (кроме кейса без источников) — реальный запрос к LLM (OpenAI). Нужны
  `LLM_PROVIDER=openai`, `LLM_API_KEY`, `LLM_MODEL` в корневом `.env`; `STAGE_VERIFICATION` не важен — eval всегда
  вызывает `real.ts`. Без этих переменных — только проверка корректности кейсов, код 0.
- Покрытие: подтверждено разными источниками → `true` / `mostly_true`; опровергнуто → `false` / `mostly_false`;
  источники противоречат → `mixed`; факт верен, вывод искажён → `misleading`; источники по теме без прямых данных
  (в том числе для заведомо верного факта — оценка «из головы» не проходит) → `unverifiable`; прогноз →
  `unverifiable`; prompt injection внутри `excerpt` (в том числе поддельный `</source>`) не меняет вердикт;
  `uiLanguage` en / uk при тезисе на другом языке; эмоциональная речь → нейтральные тексты.
- По кейсу: допустимые `label`, диапазон `score`, при необходимости — `stance` отдельных источников и запрещённые
  подстроки. Для любого выхода: `score` ↔ `label` по шкале, `null` только у `unverifiable`, `sourceAssessments`
  ровно по входным источникам, язык `summary` / `explanation` по алфавиту (латиница / кириллица, і/ї/є/ґ против
  ы/э/ъ), нейтральность — по списку оценочных слов (эвристика), `summary` не длиннее 300 символов.
- Итог — таблица PASS/FAIL с причинами и `N/M`; код выхода 1, если провален хоть один кейс.
