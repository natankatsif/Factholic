# 04 — Source search: тезис → источники с разных точек зрения

**Владелец:** backend-2

Для одного тезиса находит несколько независимых источников. Вызывается параллельно для всех тезисов куска.

|        | Тип                                                                                      | Файл       |
| ------ | ---------------------------------------------------------------------------------------- | ---------- |
| Вход   | `SourceSearchInput` (`Claim` + лимиты)                                                   | `types.ts` |
| Выход  | `SourceSearchOutput` (`FoundSource[]` + запросы)                                         | `types.ts` |
| Пример | `mockSourceSearchInput`, `mockSourceSearchOutput`                                        | `mock.ts`  |
| Mock   | `STAGE_SOURCE_SEARCH=mock` → mock-функция в конце `mock.ts`                              | `mock.ts`  |
| Real   | `STAGE_SOURCE_SEARCH=real` в `.env`, нужны: `SEARCH_PROVIDER`, `SEARCH_API_KEY`, `LLM_*` | `real.ts`  |

## Разнообразие точек зрения

Не брать 5 статей из одного издания. Стараться покрыть:

- разные **типы**: международные организации, гос. органы, СМИ, академические, фактчекеры;
- разные **страны** (`country`) и **языки**;
- источники, которые могут **опровергать** тезис (отдельный запрос в духе «миф / опровержение / fact check»).

## Поля

- `excerpt` — длинный текст для LLM на этапе 05, во фронт не уходит.
- `snippet` — 1–2 предложения, показываются в карточке источника.
- `domainReliability` — из своего справочника доменов, учитывается при оценке.

## Реализация (`real.ts`)

1. `queries.ts` — LLM составляет 3–5 запросов: по каждому языку, один на опровержение, `freshness` для свежих
   событий. Временный сбой LLM → простые запросы из тезиса и сущностей.
2. `engines.ts` — Tavily (`search_depth: advanced`, сразу с текстом страницы, соцсети и видеохостинги исключены)
   и, если задан `GOOGLE_FACTCHECK_API_KEY`, Google Fact Check Tools. Не больше 6 запросов к поиску одновременно.
3. `select.ts` + `text.ts` — дедупликация по URL, отсев не по теме (доля ключевых слов тезиса/запроса < 0.25),
   вырезка `excerpt` (до 2000 символов) и `snippet`, определение языка страницы, жадный отбор `maxSources`
   с бонусами за новый тип, страну, язык и запрос-опровержение; не больше одного источника на издателя.
4. `domains.ts` — справочник доменов (издатель, тип, страна, надёжность) + эвристики по доменной зоне
   (`.gov`, `.edu`, `.int`, ccTLD). Политика наполнения — в комментарии в начале файла.

- `.env`: `STAGE_SOURCE_SEARCH=real`, `SEARCH_PROVIDER=tavily`, `SEARCH_API_KEY`, `LLM_*` (как у 03),
  опционально `GOOGLE_FACTCHECK_API_KEY`.
- Ничего не нашли → `sources: []` (этап 05 вернёт `unverifiable`). Упали все поисковые запросы → исключение,
  оркестратор пометит тезис `failed`.
- Ручной прогон: `npm run stage:04 -w backend [-- "свой тезис"]`.

## Eval

Эталонные тезисы — `eval/cases.ts` (8 штук: ru / en / uk; событие, статистика, история, наука, миф, цитата),
прогон — `eval/run.ts`:

```bash
npm run eval:04 -w backend                          # все кейсы
npm run eval:04 -w backend -- --only measles        # по подстроке id (можно несколько через запятую)
npm run eval:04 -w backend -- --verbose             # + запросы, источники и лог этапа по каждому кейсу
```

- **Прогон платный**: на кейс — запрос к LLM (OpenAI, составление запросов) и 3–5 запросов к Tavily с
  `search_depth: advanced` (+ Google Fact Check, если задан `GOOGLE_FACTCHECK_API_KEY`). Нужны `SEARCH_PROVIDER=tavily`,
  `SEARCH_API_KEY`, `LLM_PROVIDER=openai`, `LLM_API_KEY`, `LLM_MODEL` в корневом `.env`; `STAGE_SOURCE_SEARCH` не
  важен — eval всегда вызывает `real.ts`. Без этих переменных — только проверка корректности кейсов, код 0.
- Проверяются метрики, а не конкретные URL (выдача меняется): от 3 до `maxSources` источников; ≥ 2 разных
  `sourceType`; ≥ 2 языков или стран; издатели и домены не повторяются; у каждого источника непустые `excerpt`
  (≤ 2000 символов) и `snippet`; есть запрос на опровержение; есть запросы на каждом из `searchLanguages`; для части
  кейсов — источник нужного типа (первоисточник для статистики, наука / фактчекеры для мифа). Если LLM не составила
  запросы и взяты простые — тоже провал: тогда меряется не промпт.
- В выходе этапа у `SearchQuery` нет `intent`, поэтому запрос на опровержение узнаётся по словам (fact check, myth,
  debunk, миф, опровержение, спростування…).
- Итог — таблица PASS/FAIL с причинами и `N/M`; код выхода 1, если провален хоть один кейс.
