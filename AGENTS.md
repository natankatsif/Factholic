# AGENTS.md — контекст проекта для любого AI-агента и нового разработчика

> Прочитай этот файл целиком перед любой задачей. Во вложенных папках (`backend/`, `extension/`,
> `packages/contracts/`) лежат свои `AGENTS.md` с правилами конкретной зоны, а в каждой папке этапа — `README.md`.

> ⛔ **Агенты не коммитят и не пушат.** Коммиты делает только человек. Агент может лишь _предложить_ коммит —
> см. раздел [«Git: коммитит только человек»](#git-коммитит-только-человек).

## 1. Что мы строим

**FactCheck** проверяет утверждения из видео, постов и ссылок **историей утверждения**, а не вердиктом
«правда/ложь». Фокус — молдавское инфопространство (источники на ro, ru, en).

1. на вход — видео (расширение находит `<video>` на странице), пост или ссылка;
2. бэкенд достаёт текст: субтитры, Whisper, OCR;
3. выделяет **проверяемые утверждения** со структурой: цифры, места, время, «вчера/сегодня», уверенность, кто сказал;
4. ищет **все публикации** об утверждении (ro, ru, en) — с датами, ссылками и текстом;
5. строит **дерево первоисточника**: кто у кого взял, корень — самая ранняя публикация;
6. на дереве — три проверки: **мутации** (где раздули), **дата корня** (старый контент, выданный за новый),
   **стороны** (кто за, кто против; перепечатки одного корня — один голос);
7. фронт показывает **отчёт**: таймлайн, дерево, флаги — и карточку на таймкоде видео.

Пример: в видео от 2 октября говорят «вчера Кишинёв завалило снегом, полметра за ночь» → корень — новость
января 2021 года про 10 см; по дороге 10 см → 30 см → полметра. Флаги: «Старый контент», «Раздули».

### Пользовательский сценарий

```
открыл видео / вставил ссылку
  → POST /api/jobs, индикатор «анализ идёт», прогресс processedUntil
  → бэк нашёл утверждение      → на его таймкоде «Проверяем…»                       (claim.detected)
  → бэк построил дерево и проверки → флаги, стороны, таймлайн, дерево                 (claim.checked)
  → клик по карточке → отчёт: первая публикация, кто у кого взял, что изменилось по дороге
```

## 2. Принципы продукта (не нарушать)

1. **Только по найденным публикациям.** Дерево, мутации и стороны строятся по реальным источникам со ссылками —
   не «из головы» модели. Мало источников — так и говорим (`few_sources`), а не догадываемся.
2. **Связь без доказательства — «вероятно».** Ребро дерева по явной ссылке — `confirmed`; по совпадению текста
   или «по данным …» без ссылки — `probable`, и UI это показывает.
3. **Разные точки зрения, честный подсчёт.** Перепечатки одной новости — один голос, а не пять.
   Источники разных типов, стран и языков.
4. **Нейтральный тон.** Тексты — без оценочных эпитетов и политической позиции; не повторяем оскорбления из речи.
5. **Проверяем факты, а не мнения.** Мнения, шутки, вопросы не извлекаются. Прогнозы извлекаются, но сторон у
   них нет (`few_sources`).
6. **Прозрачность.** Всегда показываем дословную цитату, первую публикацию, ссылки на все узлы дерева и что
   именно изменилось по дороге.

## 3. Архитектура

```
 [extension / ссылка]                 [backend-1: всё до поиска]
 видео, пост, ссылка ─POST /api/jobs─▶ 01 ingest           → куски звука / субтитров / текста, дата публикации
                                       02 transcription    → TranscriptSegment[]: субтитры, Whisper, OCR
                                       03 claim-extraction → Claim + structure ─────────────────▶ WS: claim.detected
                                       04 source-search    → SourceSearchOutput: sources + copies
                                      ─────────────── граница: Claim + SourceSearchOutput ───────────────
                                      [backend-2: дерево и проверки]
                                       05 provenance       → ProvenanceTree (узлы, связи, корень, voteGroups)
                                            ├─▶ 06 mutations   MutationsOutput
                                            ├─▶ 07 root-date   RootDateOutput (флаг «старый контент»)
                                            └─▶ 08 stances     StancesOutput (consensus)
 отчёт ◀───────────────────WS──────── 09 report          → FactCheck (consensus + provenance) ──▶ WS: claim.checked
```

- Куски видео обрабатываются **по порядку**, тезисы внутри куска — **параллельно** (`backend/src/pipeline/orchestrator.ts`).
  После дерева (05) мутации (06) и стороны (08) идут параллельно, дата корня (07) — чистая функция.
  Ошибка дерева не валит тезис: отчёт придёт без `provenance`, но со сторонами.
- Каждый этап — функция `Stage<Input, Output> = (input, ctx: StageContext) => Promise<Output>`
  (`backend/src/pipeline/context.ts`). Этапы **не импортируют реализации друг друга** — только типы (`types.ts`).
  Связывает их только оркестратор.
- Протокол: `POST /api/jobs` → `{ jobId, eventsUrl }` → WebSocket. Сервер шлёт `ServerEvent`, клиент шлёт
  `ClientMessage` (позиция плеера, звук в live-режиме, отмена). Всё в `packages/contracts/src/api.ts`.

### Этапы

| #   | Папка `backend/src/stages/` | Вход → Выход                                     | Владелец  | Суть                                                                          |
| --- | --------------------------- | ------------------------------------------------ | --------- | ----------------------------------------------------------------------------- |
| 01  | `01-ingest`                 | `IngestInput` → `IngestOutput`                   | backend-1 | видео / пост / ссылка → куски; дата публикации                                |
| 02  | `02-transcription`          | `TranscriptionInput` → `TranscriptionOutput`     | backend-1 | текст: субтитры, Whisper (пословные таймкоды), OCR                            |
| 03  | `03-claim-extraction`       | `ClaimExtractionInput` → `ClaimExtractionOutput` | backend-1 | утверждения + `structure` (цифры, места, время, маркеры, уверенность, автор)  |
| 04  | `04-source-search`          | `SourceSearchInput` → `SourceSearchOutput`       | backend-1 | ro/ru/en; `sources` (разнообразные) + `copies` (все копии с датами, ссылками) |
| 05  | `05-provenance`             | `ProvenanceInput` → `ProvenanceTree`             | backend-2 | дерево: ссылки → «по данным» → дубли по эмбеддингам → даты; корень            |
| 06  | `06-mutations`              | `MutationsInput` → `MutationsOutput`             | backend-2 | LLM сравнивает структуру родителя и потомка: где раздули                      |
| 07  | `07-root-date`              | `RootDateInput` → `RootDateOutput`               | backend-2 | флаг «старый контент»: корень раньше заявленной даты (код, без LLM)           |
| 08  | `08-stances`                | `StancesInput` → `StancesOutput`                 | backend-2 | позиции источников → сходятся / разделились / против / мало источников        |
| 09  | `09-report`                 | `ReportInput` → `FactCheck` (из contracts)       | backend-2 | чистый маппер во фронтовую модель                                             |

**Переходный период.** Старые этапы `05-verification` (вердикт 0–10) и `06-delivery` пока лежат рядом с новыми:
на них работает текущий оркестратор. Когда backend-1 доделает 03 (`structure`) и 04 (`copies`), он переключает
оркестратор на 05–09 и удаляет старые папки (и их юниты в `scripts/units.mjs`). Новые поля на границе
(`Claim.structure`, `FoundSource.links`/`dateFrom`, `SourceSearchOutput.copies`) пока **необязательные** —
этапы backend-2 работают и без них (05 сам извлекает структуру, дерево строится по `sources`).

### Режимы получения звука

- `remote` — бэкенд сам качает по `pageUrl` (yt-dlp). Если есть субтитры платформы — берём их, ASR не нужен.
  Можно обрабатывать наперёд.
- `live` — видео нельзя скачать (`blob:`, DRM, закрытые сайты). Расширение захватывает звук вкладки
  (`chrome.tabCapture` + offscreen document) и шлёт `audio.chunk` по WS. Оценки приходят с задержкой.

## 5. Контракты — два уровня

| Уровень       | Где                                | Кто использует               | Как менять                                 |
| ------------- | ---------------------------------- | ---------------------------- | ------------------------------------------ |
| Сетевой       | `packages/contracts/src/*`         | бэкенд **и** расширение      | только по договорённости всех троих        |
| Между этапами | `backend/src/stages/NN-*/types.ts` | следующий этап + оркестратор | договориться с владельцем следующего этапа |

Правила:

- **Типы — источник правды.** Сначала меняешь тип, потом код. Не дублируй типы в других местах — импортируй.
- Меняешь тип → **обнови `mock.ts`** того же этапа (и мок в contracts, если менял `FactCheck`). Моки — живая
  документация и данные для дизайна; они должны компилироваться.
- Внутренние поля пайплайна (`excerpt`, `domainReliability`, `checkworthiness`, `model`…) **не попадают** в
  `packages/contracts`. Фронт знает только `FactCheck` и протокол.
- Все времена — **абсолютные секунды от начала видео** (`Seconds`, дробные). Строка «20:21–20:23» — только
  через `formatRange()` на фронте.
- Оценки 0–10 больше нет (`FactCheck.verdict` — `@deprecated`, всегда `null`). Вместо неё `consensus`
  (стороны) и `provenance` (дерево, мутации, флаги). Правило подсчёта сторон — в `backend/src/stages/08-stances/README.md`.
- Граница backend-1 ↔ backend-2 — `03-claim-extraction/types.ts` и `04-source-search/types.ts`: меняете — вдвоём.

## 7. Как агенту выполнять задачу

1. Определи юнит. Прочитай его `README.md`, `types.ts`, `mock.ts` и `AGENTS.md` зоны.
2. Входные данные этапа смотри в `mock.ts` **предыдущего** этапа, выход должен совпадать по форме с `mock.ts` своего.
3. Реализуй в `real.ts` (можно добавлять файлы в папку этапа). Сигнатуру экспортируемой функции не менять.
   Проверяй со своим этапом в `real`, остальными в `mock` (см. «Mock и real»).
4. Не трогай `types.ts`, если задача этого не требует. Если требует — см. раздел 5.
5. Запусти `npm run check -- <юнит>`; для бэкенда end-to-end — `npm run dev` и подключись к WS.
6. Секреты (API-ключи ASR/LLM/поиска) — только в `.env` (он в `.gitignore`), читаются только через `backend/src/config.ts`.
   Никогда в код, никогда в `.env.example`.
7. В отчёте: что сделано, какие юниты/контракты затронуты, что осталось TODO.
8. Если работа логически закончена и `npm run check` зелёный — **предложи коммит** (см. следующий раздел).

## Git: коммитит только человек

Агент (Claude Code, Codex, Cursor, любой другой) **никогда не выполняет** `git commit`, `git push`, `git add`,
`git merge`, `git rebase`, `git reset`, `git stash`, не создаёт и не удаляет ветки и теги — даже если пользователь
попросил «сделай всё». Исключение — только явная фраза пользователя вида «закоммить сам» в текущем сообщении.
Чтение можно: `git status`, `git diff`, `git log`, `git show`, `git blame`.

Когда работа дошла до логической точки (фича/фикс готов, `npm run check` зелёный), агент в конце ответа
**предлагает** коммит — одним блоком, который человек может скопировать:

```
💾 Предлагаю закоммитить (юнит: backend-03-claim-extraction):

git add backend/src/stages/03-claim-extraction/
git commit -m "03: извлечение тезисов через LLM со structured output"
```

- В `git add` — только файлы своей задачи, перечисленные явно (не `git add -A` / `git add .`).
- Сообщение — на русском, в начале номер этапа или зона (`03:`, `ext:`, `contracts:`, `core:`).
- Если затронут контракт — сказать об этом рядом с предложением.
- Предлагать не после каждой правки, а когда есть законченный, проверенный кусок.

Как это обеспечено:

- `.claude/settings.json` (общий, в git) — Claude Code запрещены `git commit` и `git push` у всех, кто работает в папке.
- `.husky/pre-commit` — если коммит запущен из оболочки Claude Code (`CLAUDECODE=1`), хук его отклоняет.
  Поэтому и человек коммитит из **обычного терминала или IDE**, а не через `!` внутри Claude Code.
- Для остальных агентов — это правило в `AGENTS.md`.

## 8. Конвенции кода

- TypeScript strict, ESM, Node 22. Импорты — с расширением `.ts` (`import … from "./types.ts"`).
- Импорт типов — только `import type` (включены `verbatimModuleSyntax` и eslint `consistent-type-imports`).
- Модули этапов: `index.ts` делает `export type * from "./types.ts"`; значения (константы) реэкспортируются
  отдельно (`export { X } from "./types.ts"`).
- Комментарии и документация — **на русском**. Идентификаторы — на английском.
- Форматирование — prettier (`printWidth: 110`), не спорим, хук всё отформатирует сам.
- `index.ts` этапа содержит только `selectImpl(...)`; логика — в `mock.ts` (mock) и `real.ts` (real).
- `real.ts` ещё не реализованного этапа бросает понятную ошибку и помечен `TODO(<владелец>)`.
- `process.env` в бэкенде — только в `src/config.ts` (eslint `no-restricted-properties`).
- Внешние вызовы (LLM, ASR, поиск) принимают `ctx.signal` для отмены, когда пользователь ушёл со страницы.
- Тестов пока нет; эталоном формы данных служат `mock.ts`.

## Проверки и pre-commit

`npm install` ставит хук через husky (`.husky/pre-commit` → `lint-staged`). При `git commit`:

1. **eslint --fix** и **prettier --write** — только по застейдженным файлам (`lint-staged.config.mjs`).
2. **tsc** — только по юнитам, которых касаются застейдженные файлы (`scripts/check.mjs --staged`).
   Каждый этап бэкенда имеет свой `tsconfig.json`, поэтому проверяется изолированно.

Что это даёт:

| Ситуация                                                            | Результат                                     |
| ------------------------------------------------------------------- | --------------------------------------------- |
| коммитишь этап 01, а в рабочей копии лежит сломанный этап 03        | ✅ коммит проходит, 03 не проверяется         |
| коммитишь сломанный этап 03                                         | ❌ блок, показан юнит, владелец и ошибки      |
| меняешь `stages/*/types.ts` или `mock.ts` и это ломает другие этапы | ❌ блок: проверяется весь бэкенд              |
| меняешь `packages/contracts/**` и это ломает бэк или расширение     | ❌ блок: проверяются backend-core и extension |
| меняешь корневые конфиги (`tsconfig.base.json`, `package.json`)     | проверяются все юниты                         |

Команды:

```bash
npm run check                  # все юниты, tsc + eslint, отчёт ✅/❌
npm run check -- 03 extension  # выбранные юниты (по подстроке id)
```

Добавил новый модуль (например `extension/src/popup` — он внутри `extension`, ничего делать не надо; новый пакет —
нужно) → добавь юнит в `scripts/units.mjs` и `tsconfig.json` для него.
Обходить хук (`--no-verify`) нельзя, кроме аварийных случаев с явным согласия команды.

## Mock и real: единая конфигурация

Всё переключается в **одном корневом `.env`** (шаблон с комментариями — `.env.example`, сам `.env` в git не попадает).
Переменные из командной строки имеют приоритет над `.env`.

| Что                        | Переменная                                                                                                                                     | Значения                | Читается в                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------- |
| режим сервера              | `SERVER_MODE`                                                                                                                                  | `pipeline` / `replay`   | `backend/src/config.ts`                           |
| все этапы по умолчанию     | `STAGES_DEFAULT`                                                                                                                               | `mock` / `real`         | `backend/src/config.ts`                           |
| конкретный этап            | `STAGE_INGEST`, `STAGE_TRANSCRIPTION`, `STAGE_CLAIM_EXTRACTION`, `STAGE_SOURCE_SEARCH`, `STAGE_PROVENANCE`, `STAGE_MUTATIONS`, `STAGE_STANCES` | `mock` / `real`         | `backend/src/config.ts`                           |
| ключи провайдеров          | `ASR_*`, `LLM_*` (в т.ч. `LLM_EMBEDDING_MODEL`), `SEARCH_*`, `GOOGLE_FACTCHECK_API_KEY`                                                        | строки                  | `backend/src/config.ts`                           |
| источник данных расширения | `EXT_DATA_SOURCE`, `EXT_BACKEND_URL`                                                                                                           | `mock` / `backend`, URL | `extension/build.mjs` → `extension/src/config.ts` |

Уровни моков:

1. **Расширение без бэкенда** — `EXT_DATA_SOURCE=mock`: события из `MOCK_EVENTS` прямо в расширении.
2. **Бэкенд-реплей** — `SERVER_MODE=replay` (`npm run dev:mock`): настоящий HTTP/WS, но события из `MOCK_EVENTS`.
3. **Пайплайн на моках** — `SERVER_MODE=pipeline`, этапы в `mock`: настоящий оркестратор, данные из `stages/*/mock.ts`.
4. **Смешанный** — свой этап в `real`, остальные в `mock`. Так каждый разработчик проверяет свой этап на живых API,
   не дожидаясь соседей. Пример для backend-2: `STAGE_CLAIM_EXTRACTION=real` + `LLM_*`.
5. **Всё real** — `STAGES_DEFAULT=real` + все ключи.

Защита: если этап включён в `real`, а нужных ключей нет, сервер **не стартует** и пишет, чего не хватает.
Опечатка в значении (`STAGE_INGEST=reall`) — тоже ошибка при старте. При запуске сервер печатает, какой этап в каком режиме.
Данные моков лежат рядом с типами каждого этапа (`stages/*/mock.ts`) намеренно: это часть контракта этапа и
принадлежит его владельцу. Централизован только **переключатель**.

## 11. Принятые решения

- **Монорепо на npm workspaces**, типы шарятся через `@news/contracts` (TS-исходники без сборки).
- **WebSocket, а не SSE**: в MV3 service worker нет `EventSource`, а для live-режима нужен канал клиент → сервер.
- **Субтитры платформы приоритетнее ASR**: быстрее, дешевле, точнее.
- **Обработка с `startFrom`**, а не с начала видео: пользователю важно то, что он смотрит сейчас.
- **Два события на тезис** (`claim.detected` → `claim.checked`): UI сразу показывает, что тезис замечен,
  проверка (поиск + LLM) занимает секунды.
- **Сборка расширения — esbuild без UI-фреймворка** на старте; фронт вправе перейти на Vite/React, контракты не меняются.
- **Дерево первоисточника вместо вердикта 0–10** (2026-10-03): главная ценность — откуда утверждение и как
  менялось. `verdict` в контракте оставлен как `@deprecated`, пока фронт переходит.
- **Разделение backend-1 / backend-2 по границе 04 → 05**: этап целиком у одного владельца, общий контракт один.

- Даты публикаций: насколько надёжно брать их из разметки страниц; что делать с перепечатками без даты.

## 13. Глоссарий

- **Job** — одна сессия анализа одного видео (`jobId`).
- **Кусок (chunk)** — ~30 с видео, единица обработки этапов 01–02.
- **Сегмент** — фраза транскрипта с таймкодами.
- **Тезис (claim)** — проверяемое утверждение из речи; `quote` — дословно, `normalized`/`claim` — самодостаточная формулировка.
- **Источник (source)** — найденная страница; `stance` — подтверждает / опровергает / смешанно / нейтрально.
- **Копии (copies)** — все найденные публикации об утверждении, включая перепечатки одного издания; сырьё для дерева.
- **Дерево первоисточника** — кто у кого взял: рёбра по ссылкам (`confirmed`), «по данным …» и дублям текста (`probable`).
- **Корень** — самая ранняя публикация без родителя.
- **Мутация** — изменение утверждения при перепечатке: цифры, место, время, уверенность, атрибуция.
- **Старый контент** — корень сильно раньше, чем заявляет видео («вчера», а первая публикация — годы назад).
- **Стороны (consensus)** — сходятся / разделились / большинство против / мало источников; перепечатки одного корня — один голос.
- **FactCheck** — итоговая сущность для фронта: утверждение + таймкод + стороны + дерево (`provenance`) + источники.
- **Юнит** — независимо проверяемая часть кода со своим владельцем (`scripts/units.mjs`).
