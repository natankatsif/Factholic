# Задание для агента: собрать кабинет структур

Собери кабинет для государственных учреждений в `web/` на React по готовому HTML. Проверяй результат по картинкам.

Сначала прочитай:

1. `AGENTS.md` в корне репозитория.
2. [[11_Кабинет_структур_Обзор]], [[12_Кабинет_структур_Экраны]], [[13_Кабинет_структур_Контракт]], [[14_Кабинет_структур_План]].
3. [Индекс экранов](00_Индекс.md) и [Токены и компоненты](02_Токены_и_компоненты.md).

## Главное

- **16 HTML это состояния, а не 16 страниц.** Не копируй каждый файл в отдельный маршрут.
- Если заметка и контракт расходятся, верен [[13_Кабинет_структур_Контракт]]. Менять название или поле надо сначала там.
- Агент не коммитит и не пушит. Коммиты делает человек.
- Папка `obsidian/` только для чтения, кроме случая, когда меняется контракт.

## Правила продукта

- Нет вердикта «правда» или «ложь».
- Корень называется «Самая ранняя из найденных». Если корня нет, так и пишем.
- Связь без доказательства показывается как вероятная.
- Нарратив собирает человек и только из реальных цитат. Система может лишь предложить группу.
- Система не предлагает скрывать, удалять или блокировать материалы.

## Порядок работы

`<skill>` это `~/.claude/plugins/marketplaces/html-to-react-skill/skills/html-to-react`. Нужен Node 18+. Команды запускай из `web/`.

### 1. Конвертация

```bash
D=../obsidian/15_Кабинет_структур_Дизайн/screens
node <skill>/scripts/h2r.mjs analyze $D/03-tree-ready/index.html --project .
```

Дальше следуй шагам навыка: `plan.json`, `generate`, поведение, `check --tsc --lint`. В плане:

- `outDir`: `src/components/cabinet`.
- Один компонент на смысловой блок: `TopBar`, `LeftMenu`, `RightPanel`, `TreeCanvas`, `PublicationNode`.
- Иконки phosphor оставь как компоненты в `icons.tsx`: этого пакета в проекте нет, новые зависимости добавляй только по согласованию.
- `.h2r/` это черновики, не оставляй их в репозитории.

### 2. Приведение к проекту

- Цвета `bg-[#...]` замени токенами из [таблицы](02_Токены_и_компоненты.md).
- `font-[Nunito,...]` замени на `font-sans`: шрифт уже подключён в `web/src/app/layout.tsx`.
- Компоненты панели, узлов и таблиц должны быть одни на все экраны.

### 3. Что нельзя оставлять статичным

В HTML размеры и положения заданы в пикселях. Это снимок, а не логика:

- положение узлов считает раскладка дерева, сотрудник может их перетаскивать;
- линии связей считаются из положения узлов, а не копируются из SVG;
- сетка холста делается фоном CSS, а не тысячей точек из SVG;
- холст двигается и масштабируется;
- ширина полоски позиций считается из `SidesSummary`;
- счётчики и шаги приходят из данных.

Вид линий бери из экрана 03. Логику дерева можно посмотреть в `web/src/components/verification/TreeView.tsx`.

### 4. Fixture для сверки

Сделай `src/components/cabinet/fixtures.ts` с данными со всех экранов. Каждое состояние открывается по адресу `?fixture=<имя>`: имена указаны в заметках экранов. Fixture работает только в разработке.

### 5. Сверка

Для каждого из 16 экранов:

```bash
node <skill>/scripts/h2r.mjs visual-diff $D/03-tree-ready/index.html \
  "http://localhost:3000/cabinet/checks/demo?fixture=tree-ready" --widths 1440
```

Для этого нужен Playwright с Chromium. Цель навыка: меньше 1% отличий. В [Сверке с картинками](03_Сверка_с_картинками.md) указан уровень, на котором сам HTML отличается от PNG: его дожать нельзя.

После цифр открой `reference.png` и свой снимок глазами. Шрифт, цвета и отступы должны совпасть. Отметь галочки в заметке экрана в своём отчёте, сами заметки не меняй.

## Чего нет в дизайне

Не придумывай это молча, спроси человека:

- вид «Хронология»: переключатель есть, экрана нет;
- карточка публикации без связи с объяснением почему;
- экран «Посмотреть цитаты» для предложения группы;
- телефон и планшет: дизайн только для ширины 1440 px.

## Открытые вопросы

- В интерфейсе встречаются «вопрос» и «тезис». Нужно выбрать одно слово.
- На экране 09 обещано, что повтор продолжит с места сбоя и не спишет лимит. Бэкенд это пока не умеет.
- «Центр коммуникаций», «Ирина К.» и лимиты 100 и 20 это заглушки.
- Все издания и утверждения на экранах вымышлены. Не показывай их на рабочем сайте.
