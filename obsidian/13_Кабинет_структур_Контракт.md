# Кабинет структур: контракт

Этот файл — договорённость между дизайном и кодом. Если меняется название, поле или действие, правим сначала его. Технические названия даны в `коде`, рядом написано простое значение.

## Как включается

API кабинета работает только с `CABINET_API=on`. Входа пока нет: на открытом сервере не включать. Плановое слежение включается отдельно, `WATCH_SCHEDULER=on`, потому что каждая проверка тратит деньги. Данные лежат в SQLite (`CABINET_DB_PATH`). Нужен постоянный диск, на Vercel файл не сохранится. Типы API пока в `backend/src/org/types.ts`, перенос в `packages/contracts` решает команда.

## Что уже есть

Можно использовать без изменений:

- `POST /api/jobs` — запустить проверку;
- WebSocket `/api/jobs/:id/events` — получать ход проверки;
- `FactCheck` — карточка утверждения;
- `ProvenanceTree` — узлы и связи дерева.

Нет входа в аккаунт, организаций, постоянной базы, слежения и уведомлений.

## Главные объекты

| Поле   | Значение                   |
| ------ | -------------------------- |
| `id`   | Номер организации          |
| `name` | Название                   |
| `plan` | Лимиты проверок и слежений |

### Сотрудник `Member`

| Поле             | Значение                 |
| ---------------- | ------------------------ |
| `id`             | Номер                    |
| `organizationId` | Организация              |
| `name`           | Имя                      |
| `email`          | Почта для входа и сводок |
| `role`           | `member` или `admin`     |

### Тезис `TrackedClaim`

Сохранённое утверждение. Одно и то же утверждение может проверяться много раз.

| Поле             | Значение                |
| ---------------- | ----------------------- |
| `id`             | Номер тезиса            |
| `organizationId` | Чей тезис               |
| `text`           | Понятная формулировка   |
| `quote`          | Дословная цитата        |
| `language`       | Язык                    |
| `sourceUrl`      | Откуда взяли, если есть |
| `createdBy`      | Кто добавил             |
| `createdAt`      | Когда добавили          |
| `latestCheckId`  | Последняя проверка      |

### Проверка `ClaimCheck`

Один запуск поиска и построения дерева.

| Поле         | Значение                                                                                |
| ------------ | --------------------------------------------------------------------------------------- |
| `id`         | Номер проверки                                                                          |
| `claimIds`   | Какие тезисы. В одном тексте их может быть несколько, становятся известны после разбора |
| `status`     | `running`, `done`, `failed`                                                             |
| `steps`      | Ход поиска                                                                              |
| `factCheck`  | Итог в нынешнем формате `FactCheck`                                                     |
| `tree`       | Дерево в нынешнем формате `ProvenanceTree`                                              |
| `startedAt`  | Начало                                                                                  |
| `finishedAt` | Конец                                                                                   |
| `costUsd`    | Внутренняя цена, сотруднику не показывается                                             |

### Уточнение `Clarification`

Вопрос модели перед проверкой. Модель получает текст, текущую дату и время и язык интерфейса. Если времени или участников не хватает, она предлагает точную формулировку. Без ответа проверка не начинается и деньги на поиск не тратятся. Вопрос ждёт в верхней панели.

| Поле        | Значение                                     |
| ----------- | -------------------------------------------- |
| `id`        | Номер                                        |
| `input`     | Что написал сотрудник                        |
| `question`  | Вопрос на языке интерфейса                   |
| `rewritten` | Новая формулировка на языке исходного текста |
| `locale`    | Язык интерфейса, он же язык текстов отчёта   |
| `status`    | `pending`, `answered`                        |

### Шаг поиска `SearchStep`

| Поле      | Значение                                                |
| --------- | ------------------------------------------------------- |
| `key`     | `claims`, `search`, `traces`, `tree`, `stances`, `done` |

### Нарратив `Narrative`

Группа вопросов, которую собрал человек. Появляется на этапе 4. Система может только предложить группу, но не создаёт её сама.

| Поле             | Значение                                      |
| ---------------- | --------------------------------------------- |
| `id`             | Номер                                         |
| `organizationId` | Чья группа                                    |
| `title`          | Короткое название                             |
| `description`    | Описание, его пишет сотрудник                 |
| `claimIds`       | Какие вопросы входят                          |
| `quotes`         | Реальные цитаты: ссылка, сайт, дата, фрагмент |
| `confirmedBy`    | Кто подтвердил                                |
| `confirmedAt`    | Когда подтвердил                              |

| --------- | ------------------ |

## Сигналы

Числа ниже — стартовые значения, их надо проверить на реальных данных.

| `type`             | Простое значение                 | Условие для старта                       | Важность  |
| ------------------ | -------------------------------- | ---------------------------------------- | --------- |
| `new_publications` | Появились новые публикации       | Хотя бы 1 новая                          | `info`    |
| `growth`           | История растёт                   | 5 новых за сутки и вдвое больше обычного | `notable` |
| `new_language`     | Пошла на другом языке            | Первая публикация на языке               | `notable` |
| `new_outlet`       | Подхватило крупное издание       | Издание из списка организации            | `notable` |
| `changed_detail`   | Изменились цифра, место или дата | Подтверждённая мутация                   | `notable` |
| `debunk_found`     | Появился разбор                  | Новый разбор или опровержение            | `info`    |
| `sides_changed`    | Изменился итог                   | Итог стал другим                         | `notable` |
| `earlier_found`    | Нашлась более ранняя публикация  | Новая самая ранняя дата                  | `notable` |
| `quiet`            | История затихла                  | 14 дней нет новых публикаций             | `info`    |

Сильные сигналы приходят сразу, обычные собираются в сводку. За один тезис и сигнал не больше одного уведомления в сутки.

## Статус тезиса

| Статус      | Простое значение             |
| ----------- | ---------------------------- |
| `new`       | Только проверили             |
| `spreading` | Растёт                       |
| `stable`    | Новых изменений мало         |
| `debunked`  | Есть разборы, это не вердикт |
| `fading`    | Затихает                     |

## События в реальном времени

Кабинет открывает одно соединение `/api/org/events`.

| Событие             | Что меняется на экране                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `check.step`        | Обновляются блок «Ход поиска» и «В процессе» в верхней панели                                |
| `tree.node.added`   | На холсте появляется публикация. **Пока не сделано**: пайплайн отдаёт дерево целиком в конце |
| `tree.edge.added`   | На холсте появляется связь. **Пока не сделано**                                              |
| `tree.root.changed` | Меняется самая ранняя из найденных. **Пока не сделано**                                      |
| `check.finished`    | В правой панели появляется итог и предложение следить                                        |
| `check.failed`      | Показывается ошибка и кнопка повтора                                                         |
| `alert.created`     | Появляется уведомление                                                                       |

Событие приходит на всех страницах кабинета, поэтому за проверкой можно следить из любого раздела.

## Как дерево будет расти

Сейчас дерево приходит только в конце проверки. Для первой версии порядок такой:

1. По мере поиска приходят публикации без связей.
2. После этапа 05 приходят связи и самая ранняя публикация.
3. После этапа 08 приходят позиции и итог.

Это честный рост: связи не рисуются раньше, чем система их определила.

## Как работает слежение

1. По расписанию система ищет новые публикации по тезису.
2. Новая публикация сравнивается с известными.
3. Если нашлось новое, строится обновлённое дерево.
4. Система сравнивает старую и новую версии.
5. Из отличий создаются уведомления.

Старые версии деревьев сохраняются, чтобы можно было показать, что изменилось.

## Ограничения и лимиты

- Проверка стоит денег, поэтому у организации есть лимит проверок и слежений.
- Для экономии слежение сначала ищет только новые адреса, а дерево пересчитывает при находке.
- Закрытые страницы показываются как закрытые, система их не обходит.
- Мы храним ссылку, заголовок, дату и нужный фрагмент, а не копию всего сайта без необходимости.
