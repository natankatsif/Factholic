# FactCheck — откуда взялось утверждение

Проверяет утверждения из видео, постов и ссылок не вердиктом «правда/ложь», а **историей утверждения**:
находит все публикации, строит **дерево первоисточника** (кто у кого взял), показывает, **где утверждение
раздули** по дороге, **не старый ли это контент**, выданный за новый, и **кто за и кто против**.
Итог — отчёт: таймлайн, дерево, флаги. Фокус — молдавское инфопространство (источники на ro, ru, en).

## Пайплайн

```
 [extension / ссылка]                 [backend-1: всё до поиска]
 видео, пост, ссылка ─POST /api/jobs─▶ 01 ingest           → куски звука / субтитров / текста, дата публикации
                                       02 transcription    → текст: субтитры, Whisper, OCR
                                       03 claim-extraction → утверждения + структура ───────────▶ claim.detected
                                                             (цифры, места, время, «вчера», кто сказал)
                                       04 source-search    → sources (разнообразные, для сторон)
                                                             + copies (все перепечатки с датами и ссылками)
                                      ─────────────── граница: Claim + SourceSearchOutput ───────────────
                                      [backend-2: дерево и проверки]
                                       05 provenance       → дерево первоисточника: связи, даты, корень
                                            ├─▶ 06 mutations   где раздули (цифры, место, время, уверенность)
                                            ├─▶ 07 root-date   старый контент: корень раньше, чем заявляет видео
                                            └─▶ 08 stances     за и против (перепечатки одного корня — один голос)
 отчёт: таймлайн, ◀──────WS──────────── 09 report         → FactCheck: consensus + provenance ──▶ claim.checked
 дерево, флаги
```

Граница между backend-1 и backend-2 — **один контракт**: выход этапа 04 (`SourceSearchOutput`:
утверждение со структурой + источники с датами, ссылками и текстом). До него — backend-1, после — backend-2.

Переходный период: оркестратор пока работает на старых этапах `05-verification` / `06-delivery` (вердикт 0–10);
backend-1 переключит его на 05–09, когда 03 и 04 начнут отдавать `structure` и `copies`.

## Роли и распределение папок

Команда: 2 бэкенд-разработчика + 1 фронтенд. Разделение по этапам целиком — у каждого этапа один владелец.

| Роль                                       | Кто   | Папки                                                                                                                                                |
| ------------------------------------------ | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **backend-1** — всё до поиска включительно | _____ | `backend/src/stages/01-ingest/`, `02-transcription/`, `03-claim-extraction/`, `04-source-search/`, `backend/src/pipeline/`, `server.ts`, `config.ts` |
| **backend-2** — дерево и проверки          | _____ | `backend/src/stages/05-provenance/`, `06-mutations/`, `07-root-date/`, `08-stances/`, `09-report/`                                                   |
| **frontend** — расширение и отчёт          | _____ | `extension/`                                                                                                                                         |
| общее, только по договорённости            | все   | `packages/contracts/`, корневые конфиги, `scripts/`                                                                                                  |

Каждый этап — отдельная функция с типизированным входом/выходом. Каждый этап включается в `mock` или `real` отдельно через `.env`,
поэтому весь пайплайн запускается end-to-end с первого дня, и никто никого не ждёт.

### 🎬 backend-1 — вход, текст, утверждения, источники

**Задача одной фразой:** из видео, поста или ссылки получить утверждения со структурой и все публикации о них — с датами, ссылками и текстом.

```
backend/src/stages/01-ingest/            видео / пост / ссылка → куски; дата публикации
backend/src/stages/02-transcription/     текст: субтитры, Whisper, OCR
backend/src/stages/03-claim-extraction/  утверждения + структура (цифры, места, время, «вчера», уверенность, кто сказал)
backend/src/stages/04-source-search/     источники ro/ru/en: sources (для сторон) + copies (все перепечатки для дерева)
backend/src/pipeline/, server.ts, config.ts  оркестратор, сервер, конфиг, кэш готовых прогонов для демо
```

**Что сделать:**

- вход: видео (`yt-dlp`, субтитры платформы), пост, ссылка на статью; **дата публикации** → `VideoInfo.publishedAt`;
- текст: субтитры → Whisper (если субтитров нет) → OCR для картинок и скриншотов;
- 03: LLM вытаскивает **структуру утверждения** (`Claim.structure`) — по этим полям backend-2 сравнивает узлы дерева;
- 04: режим `copies` — **все перепечатки без отсева по издателю**; у каждой — дата (поиск → разметка страницы → URL),
  ссылки из текста, кусок текста; запрос **самого раннего упоминания** (Tavily `start_date` / `end_date`);
- оркестратор и сервер: кэш готовых прогонов по URL для демо, `GET /api/jobs/:id`, отмена, ошибки.

**Отдаёт backend-2:** `Claim` (со структурой) и `SourceSearchOutput` (`sources` + `copies`).

### 🧠 backend-2 — дерево первоисточника и проверки

**Задача одной фразой:** по всем копиям утверждения восстановить, откуда оно взялось и как менялось, и собрать отчёт.

```
backend/src/stages/05-provenance/   дерево: явные ссылки → «по данным …» → дубли по эмбеддингам → сортировка по дате; корень
backend/src/stages/06-mutations/    LLM сравнивает структуру родителя и потомка: цифры / место / время / уверенность
backend/src/stages/07-root-date/    «старый контент»: корень сильно раньше, чем заявляет видео (код, без LLM)
backend/src/stages/08-stances/      стороны: за / против / нейтрально → сходятся / разделились / против / мало источников
backend/src/stages/09-report/       всё вместе → FactCheck (consensus + provenance) для фронта
```

**Порядок:** дерево → дата корня (дёшево и эффектно для демо) → мутации → стороны (вторичны — режем первыми, если не успеваем).

**Получает от backend-1:** `Claim` + `SourceSearchOutput`. **Отдаёт фронту** (через оркестратор): `FactCheck`.

### 🎨 frontend — расширение и отчёт

**Папки:** `extension/`. **Задача:** отчёт — таймлайн публикаций, дерево первоисточника, флаги («старый контент»,
«раздули»), стороны; карточка утверждения на таймкоде видео. Данные для дизайна — `MOCK_VIDEO_REPORT`
(пример дерева со старым контентом и раздутыми цифрами — `clm_09`).
**Получает:** `ServerEvent` / `FactCheck` из `@news/contracts`. **Отдаёт:** `StartAnalysisRequest`, `ClientMessage`.

### Где роли встречаются

```
frontend ──StartAnalysisRequest──▶ backend-1 ──Claim + SourceSearchOutput──▶ backend-2
frontend ◀────────────ServerEvent / FactCheck (через оркестратор)─────────── backend-2
```

- Граница **backend-1 ↔ backend-2**: `03-claim-extraction/types.ts` и `04-source-search/types.ts`. Меняете — договариваетесь вдвоём.
- Граница **бэкенд ↔ фронт**: `packages/contracts/`. Меняется только втроём.
- Коммитит каждый сам свои папки; pre-commit проверяет только то, что вы коммитите (см. ниже).

## Для фронта / дизайна

- Модель: `packages/contracts/src/fact-check.ts` → `FactCheck`: `consensus` (стороны) и `provenance`
  (дерево, таймлайн, мутации, флаги). `verdict` (0–10) — старая концепция, больше не заполняется.
- Мок: `packages/contracts/src/mocks/video-report.mock.ts` → `MOCK_VIDEO_REPORT`

## Коммиты делают люди, а не AI-агенты

Агенты (Claude Code, Codex, Cursor…) не коммитят и не пушат — только **предлагают** готовые команды
`git add …` + `git commit -m "…"`, а вы их выполняете из обычного терминала или IDE.
Для Claude Code это включено у всех через `.claude/settings.json` и `.husky/pre-commit`; подробно — в
[AGENTS.md](AGENTS.md#git-коммитит-только-человек).

## Pre-commit: проверки по юнитам, а не по всему репо

При `git commit` хук проверяет **только то, что ты коммитишь**:

1. `eslint --fix` + `prettier` — по застейдженным файлам.
2. `tsc` — по **юнитам**, которых касаются эти файлы (реестр в `scripts/units.mjs`).

Сломанный незакоммиченный код в чужом этапе твой коммит **не** блокирует. Свой сломанный — блокирует,
с указанием юнита и владельца. Изменение **контракта** (`packages/contracts/**`, `stages/*/types.ts`, `stages/*/mock.ts`)
дополнительно проверяет всех, кто от него зависит — нельзя молча сломать соседа.

Подробно — в [AGENTS.md](AGENTS.md#проверки-и-pre-commit).
